# UI MVP Scope

## 1. 目标

本文件定义第一轮 UI 原型生成范围，避免一次生成过大、页面质量不稳定。

建议先用 Stitch 生成桌面端高保真原型，再根据结果拆分到前端实现。

## 2. 第一轮必须生成的页面

第一轮建议生成 8 个核心页面：

1. 首页。
2. 简历上传页。
3. 简历解析校对页。
4. AI 访谈页。
5. 人才画像页。
6. 简历生成页。
7. HR 候选人推荐列表页。
8. 候选人匹配详情页。

这些页面可以完整表达产品核心价值。

## 3. 第二轮补充页面

第二轮再生成：

- HR 岗位需求输入页。
- 岗位画像确认页。
- HR 导出包页。
- 内部调试页。
- 登录 / 注册页。
- 设置页。

## 4. 第一轮不做

第一轮 UI 原型不建议做：

- 手机端完整适配。
- 企业复杂权限。
- ATS API 配置页。
- 支付页。
- 候选人大规模搜索。
- 多租户管理后台。
- 复杂数据分析仪表盘。

## 5. 第一轮页面目标

### 5.1 首页

目标：

- 讲清产品定位。
- 引导候选人开始流程。
- 暗示 HR 兼容传统工作流。

### 5.2 简历上传页

目标：

- 上传简历。
- 强调建议使用结构清晰文件。
- 提供隐私和复杂模板提示。

### 5.3 简历解析校对页

目标：

- 展示 AI 解析结果。
- 允许校对和修正。
- 体现解析质量。

### 5.4 AI 访谈页

目标：

- 展示 AI 基于简历追问。
- 展示访谈阶段和问题原因。
- 支持跳过和结束生成画像。

### 5.5 人才画像页

目标：

- 展示 8 个能力维度。
- 展示优势、风险、职业偏好和证据。
- 强调评分不是绝对判断。

### 5.6 简历生成页

目标：

- 展示 ATS 版和 HR 版简历。
- 支持复制和导出。
- 强调不编造事实。

### 5.7 HR 推荐列表页

目标：

- 展示候选人排序。
- 展示匹配分、分项分和风险标签。
- 支持复制摘要和加入导出包。

### 5.8 候选人匹配详情页

目标：

- 展示推荐理由、风险点和面试问题。
- 展示证据和置信度。
- 支持导出推荐包。

## 6. Stitch 生成策略

不要一次让 Stitch 生成所有细节页面。

推荐顺序：

1. 先生成首页 + 候选人主流程 5 页。
2. 再生成 HR 侧 2-3 页。
3. 最后统一设计系统和组件样式。

每轮生成后都要检查：

- 页面是否符合流程。
- 信息是否过多。
- AI 结论是否有证据入口。
- HR 输出是否有复制/导出按钮。
- 视觉是否专业可信。

## 7. 原型验收标准

第一轮 UI 原型通过标准：

- 用户能看懂从上传简历到生成简历的路径。
- 人才画像页能清晰展示评分、证据、风险和置信度。
- HR 页面能体现传统工作流兼容：复制、导出、摘要、面试问题。
- 页面不显得像普通聊天机器人。
- 页面不显得像传统厚重 HR 系统。
- 整体视觉专业、清晰、可信。
