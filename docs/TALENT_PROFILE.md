# Talent Profile Design

## 1. 设计目标

人才画像是 AI Talent Agent 的核心资产。

它的目标不是给候选人贴标签，而是把简历和访谈中的信息转化为可解释、可匹配、可生成简历的结构化理解。

人才画像必须满足：

- 可解释：每个结论都有证据。
- 可追溯：证据来自简历或访谈。
- 可修正：信息不足时允许低置信度。
- 可匹配：能参与岗位匹配。
- 可生成：能支撑不同版本简历生成。

## 2. 画像结构

Talent Profile 建议包含以下部分：

- 基础摘要。
- 能力评分。
- 核心优势。
- 潜在风险。
- 职业偏好。
- 推荐岗位方向。
- 证据链。
- 置信度。

示例结构：

```json
{
  "summary": "候选人整体画像摘要",
  "capabilityScores": {},
  "strengths": [],
  "risks": [],
  "careerPreferences": {},
  "recommendedRoles": [],
  "evidence": [],
  "confidence": "medium"
}
```

## 3. 评分机制

建议 MVP 使用 1-5 分制，而不是 0-100 分。

原因：

- 1-5 分更适合早期主观评估。
- 避免伪精确。
- 更容易解释给用户和 HR。

评分含义：

| 分数 | 含义 |
| --- | --- |
| 1 | 证据不足或明显较弱 |
| 2 | 有少量信号，但不稳定 |
| 3 | 达到一般岗位要求 |
| 4 | 有明确正向证据，表现较强 |
| 5 | 多个强证据支持，表现突出 |

每个评分必须包含：

- score：1-5。
- reason：评分理由。
- evidenceIds：证据 ID。
- confidence：high / medium / low。

## 4. 置信度机制

置信度不等于能力强弱，而是表示结论依据是否充分。

| 置信度 | 含义 |
| --- | --- |
| high | 有多个简历或访谈证据支持 |
| medium | 有部分证据支持，但仍有缺口 |
| low | 信息不足，只能做弱判断 |

规则：

- 信息不足时不得强行给出确定结论。
- 低置信度结论必须提示“需要进一步访谈或面试验证”。
- HR 侧展示风险时应优先展示低置信度关键项。

## 5. 证据来源

证据分为两类：

### 5.1 Resume Evidence

来自简历：

- 教育经历。
- 工作经历。
- 项目经历。
- 技能标签。
- 证书。
- 成果描述。

### 5.2 Interview Evidence

来自访谈：

- 对经历的解释。
- 对项目难点的描述。
- 对个人贡献的澄清。
- 对失败和复盘的回答。
- 对职业偏好的表达。

证据结构：

```json
{
  "id": "evidence_001",
  "source": "resume",
  "type": "project",
  "content": "负责某项目的核心模块设计和交付",
  "relatedCapability": ["executionAbility", "logicAbility"]
}
```

## 6. 八大能力维度

### 6.1 学习能力

定义：

候选人面对新知识、新工具、新业务时，能否快速理解、吸收并应用。

正向证据：

- 短时间掌握新技术或新业务。
- 从非相关背景切换到新岗位并产生成果。
- 主动学习并应用到实际项目。
- 能清晰描述学习路径和方法。

风险信号：

- 经历长期重复，缺少能力扩展。
- 无法解释自己如何掌握关键技能。
- 学习行为只停留在“看过、了解”。

访谈关注：

- 最近一次快速学习新东西是什么。
- 遇到不熟悉任务时如何拆解。
- 学习结果如何落到具体产出。

### 6.2 逻辑能力

定义：

候选人能否结构化分析问题、识别因果、拆解复杂任务并做出合理判断。

正向证据：

- 能清晰描述项目背景、问题、方案和结果。
- 能解释关键决策背后的权衡。
- 能把复杂问题拆成可执行步骤。
- 有数据分析、流程优化或系统设计经历。

风险信号：

- 描述经历时只有结果，没有过程。
- 无法解释为什么选择某个方案。
- 回答跳跃，缺少因果链。

访谈关注：

- 项目中最复杂的问题是什么。
- 当时有哪些方案，为什么选现在的方案。
- 如何判断方案有效。

### 6.3 沟通能力

定义：

候选人能否清晰表达、理解他人需求、协调多方并推动共识。

正向证据：

- 跨团队协作经历。
- 面向客户、业务、管理层表达过方案。
- 能处理需求冲突或沟通分歧。
- 能把复杂内容讲清楚。

风险信号：

- 所有贡献都只描述为个人执行。
- 回答中无法体现协作对象和沟通过程。
- 遇到冲突时只回避或上交。

访谈关注：

- 最近一次沟通冲突如何处理。
- 如何确认对方真实需求。
- 如何向非专业对象解释复杂问题。

### 6.4 执行能力

定义：

候选人能否把目标拆解为行动，并在约束下稳定交付结果。

正向证据：

- 有明确交付物。
- 能描述时间、资源和优先级管理。
- 在压力或不确定情况下完成任务。
- 结果有数据、上线、收入、效率提升等体现。

风险信号：

- 经历描述停留在“参与、协助”。
- 缺少个人贡献和最终结果。
- 对延期、失败或问题没有复盘。

访谈关注：

- 你具体负责哪一部分。
- 如何保证按时完成。
- 遇到阻碍时如何推进。

### 6.5 创新能力

定义：

候选人能否提出新方法、新方案或新视角，并将其应用到真实问题中。

正向证据：

- 主动提出改进方案。
- 优化流程、工具或产品体验。
- 有从 0 到 1 的项目经历。
- 能用不同方式解决旧问题。

风险信号：

- 所有工作都严格按指令执行。
- 没有主动改进案例。
- 无法解释方案创新点。

访谈关注：

- 有没有主动改进过某个流程或方案。
- 为什么想到这个方法。
- 结果是否被采纳或产生影响。

### 6.6 领导能力

定义：

候选人能否影响他人、组织资源、推动团队完成目标。

正向证据：

- 带人、带项目或担任负责人。
- 协调多方资源完成目标。
- 在没有正式权力时推动他人协作。
- 能复盘团队协作和分工。

风险信号：

- 只强调个人能力，没有团队视角。
- 无法说明如何分配任务或处理团队问题。
- 对团队失败完全归因于他人。

访谈关注：

- 是否负责过项目或小组。
- 如何分配任务。
- 团队遇到分歧时如何处理。

### 6.7 抗压能力

定义：

候选人在高压力、复杂变化或失败情况下，能否保持稳定行动和复盘能力。

正向证据：

- 在紧急项目、业务变化、资源不足下完成目标。
- 能描述压力来源和应对策略。
- 有失败复盘和调整行为。
- 不把压力完全归咎于外部。

风险信号：

- 回避困难经历。
- 对失败没有反思。
- 压力下只依赖他人决策。

访谈关注：

- 压力最大的一次经历是什么。
- 当时如何处理。
- 之后有什么改变。

### 6.8 职业稳定性

定义：

候选人的职业选择是否有连续性，岗位偏好和发展方向是否相对清晰。

正向证据：

- 职业路径有可解释的连续性。
- 换工作或转方向有明确原因。
- 对未来岗位、行业和工作方式有清晰偏好。
- 过往经历与目标方向有一定关联。

风险信号：

- 频繁变动且原因不清。
- 对目标岗位没有清晰认知。
- 选择理由高度外部化，如只看薪资或短期机会。

访谈关注：

- 为什么选择当前方向。
- 上一次变化的原因是什么。
- 下一份工作最看重什么。

## 7. 输出视角

### 7.1 候选人视角

表达应更偏成长和建议：

- 你的核心优势。
- 你可以重点表达的经历。
- 你的潜在短板。
- 适合的岗位方向。
- 简历优化建议。

### 7.2 HR 视角

表达应更偏匹配和验证：

- 候选人与岗位的适配点。
- 不确定或风险点。
- 需要面试验证的问题。
- 候选人的潜力和限制。

## 8. 禁止规则

Profile Agent 生成画像时不得：

- 编造候选人没有提供的经历。
- 把低置信度结论写成确定事实。
- 用歧视性、人格化、不可验证标签描述候选人。
- 只给结论不给证据。
- 根据学校、年龄、性别等信息做不当推断。

## 9. 后续扩展维度

MVP 稳定后可考虑增加：

- 商业敏感度。
- 产品感。
- 技术深度。
- 数据能力。
- 客户意识。
- 自驱力。
- 组织协作偏好。

这些维度不建议第一版全部加入，避免画像过重。
