# User Flow

## 1. 目标

本文件定义 AI Talent Agent 的 UI 用户流程，用于指导页面生成、原型设计和后续前端开发。

UI 设计应服务两个核心闭环：

- 候选人侧：上传简历 -> 校对解析 -> AI 访谈 -> 人才画像 -> 简历生成。
- HR 侧：输入岗位 -> 查看推荐 -> 查看匹配详情 -> 导出到现有工作流。

## 2. 角色路径

### 2.1 Candidate Path

候选人路径优先级最高。

```text
首页
  -> 简历上传
  -> 解析中
  -> 简历解析校对
  -> AI 访谈
  -> 人才画像
  -> 简历生成
  -> 导出 / 复制
```

### 2.2 HR Path

HR 路径作为第二阶段，但 UI 可以先做原型。

```text
首页
  -> HR 入口
  -> 岗位需求输入
  -> 岗位画像确认
  -> 候选人推荐列表
  -> 候选人匹配详情
  -> 导出候选人推荐包
```

### 2.3 Internal Operator Path

内部调试路径用于查看 Agent 运行过程。

```text
内部入口
  -> Agent 运行记录
  -> 输入输出 JSON
  -> Prompt 版本
  -> 画像 / 匹配质量检查
```

## 3. 候选人侧详细流程

### 3.1 首页

目标：

- 让用户理解产品不是普通简历润色工具，而是先理解候选人再生成简历。
- 引导用户开始上传简历。

主要动作：

- 点击“开始生成我的人才画像”。
- 点击“查看 HR 侧演示”。

下一步：

- 进入简历上传页。

### 3.2 简历上传

目标：

- 获取用户简历文件。
- 告知用户复杂模板可能影响解析质量。

主要动作：

- 上传 PDF / Word。
- 查看支持格式说明。
- 查看隐私提示。

异常：

- 文件格式不支持。
- 文件过大。
- 文本提取失败。
- 简历模板过于复杂。

下一步：

- 上传成功后进入解析中状态。

### 3.3 解析中

目标：

- 告知用户系统正在提取简历内容。

展示内容：

- 当前步骤：提取文本、识别经历、生成结构化信息。
- 进度提示。
- 简短说明：解析结果稍后可以校对。

下一步：

- 成功进入简历解析校对页。
- 失败进入错误提示，并允许重新上传或手动录入。

### 3.4 简历解析校对

目标：

- 让用户确认 AI 解析结果。
- 避免错误数据进入画像。

页面模块：

- 基础信息。
- 教育经历。
- 工作经历。
- 项目经历。
- 技能标签。
- 解析质量提示。

主要动作：

- 编辑字段。
- 删除错误条目。
- 添加缺失经历。
- 点击“确认并开始 AI 访谈”。

下一步：

- 进入 AI 访谈页。

### 3.5 AI 访谈

目标：

- 围绕简历缺口和画像维度补充证据。

页面模块：

- 聊天区域。
- 当前访谈阶段。
- 轮数进度。
- 本轮问题原因。
- 可跳过按钮。

主要动作：

- 回答问题。
- 跳过问题。
- 结束访谈并生成画像。

异常：

- 用户回答太短。
- 用户连续跳过。
- AI 无法生成有效问题。

下一步：

- 信息足够后进入人才画像页。

### 3.6 人才画像

目标：

- 展示系统对候选人的结构化理解。

页面模块：

- 总体摘要。
- 8 个能力维度评分。
- 核心优势。
- 潜在风险。
- 职业偏好。
- 推荐岗位方向。
- 证据链。
- 置信度提示。

主要动作：

- 查看证据。
- 展开能力维度详情。
- 点击“生成简历版本”。

下一步：

- 进入简历生成页。

### 3.7 简历生成

目标：

- 基于人才画像生成可用简历。

页面模块：

- 简历版本选择：ATS 版、HR 版、平台简介、邮件正文。
- 简历预览。
- 生成依据提示。
- 导出按钮。

主要动作：

- 切换版本。
- 复制内容。
- 导出 Word / PDF。
- 返回画像继续查看。

## 4. HR 侧详细流程

### 4.1 HR 入口

目标：

- 说明 HR 可以继续使用原有工具，本系统只增强候选人理解。

主要动作：

- 点击“输入岗位需求”。
- 查看示例岗位。

### 4.2 岗位需求输入

目标：

- 让 HR 用自然语言描述岗位需求。

页面模块：

- 大文本输入框。
- 示例需求。
- 关键字段提示：岗位、年限、技能、职责、软能力。

主要动作：

- 输入岗位需求。
- 点击“生成岗位画像”。

下一步：

- 进入岗位画像确认页。

### 4.3 岗位画像确认

目标：

- 让 HR 确认 AI 对岗位需求的拆解是否正确。

页面模块：

- 岗位名称。
- 工作年限。
- 核心职责。
- 必备技能。
- 加分技能。
- 能力要求。
- 缺失信息提示。

主要动作：

- 编辑岗位画像。
- 点击“开始匹配候选人”。

下一步：

- 进入候选人推荐列表。

### 4.4 候选人推荐列表

目标：

- 展示匹配候选人，并让 HR 快速理解排序原因。

页面模块：

- 候选人卡片。
- 总匹配分。
- 分项得分。
- 关键推荐理由。
- 风险标签。
- 筛选和排序。

主要动作：

- 查看详情。
- 复制摘要。
- 加入导出包。

下一步：

- 进入候选人匹配详情页。

### 4.5 候选人匹配详情

目标：

- 解释为什么推荐该候选人，以及面试需要验证什么。

页面模块：

- 候选人基础摘要。
- 匹配分拆解。
- 推荐理由。
- 风险点。
- 证据来源。
- 建议面试问题。
- 简历预览。

主要动作：

- 复制推荐理由。
- 复制面试问题。
- 导出候选人推荐包。

### 4.6 导出候选人推荐包

目标：

- 让 HR 把结果带回已有工作流。

支持输出：

- Excel / CSV。
- 候选人一页摘要。
- 邮件正文。
- 飞书 / 企业微信 / 钉钉摘要。
- 面试评价表。

## 5. 空状态与失败路径

### 5.1 无简历

提示用户上传简历，并说明支持格式。

### 5.2 解析失败

提供：

- 重新上传。
- 手动录入。
- 查看解析失败原因。

### 5.3 访谈信息不足

提示：

- 当前画像置信度较低。
- 建议继续回答 2-3 个问题。
- 也可以直接生成低置信度画像。

### 5.4 无候选人可匹配

提示 HR：

- 当前人才库暂无候选人。
- 可以先导入候选人简历。
- 可以查看示例数据。

### 5.5 导出失败

提供：

- 重试。
- 复制纯文本。
- 下载 JSON。
