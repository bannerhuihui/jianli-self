# PRD：AI Talent Agent MVP

## 1. 版本目标

MVP 的目标是验证 AI Talent Agent 的核心闭环：

```text
候选人简历 -> AI 访谈 -> 人才画像 -> 简历生成 -> 岗位匹配
```

研发顺序上，建议先完成候选人侧闭环，再接入 HR 侧匹配。

## 2. 用户角色

### 2.1 Candidate

候选人，希望通过 AI 理解自己的经历、能力和职业方向，并生成更适合投递的简历。

### 2.2 HR

招聘方，希望通过自然语言描述岗位需求，并获得基于人才画像的候选人推荐。

### 2.3 Internal Operator

内部运营或产品人员，用于检查 Agent 输出、Prompt 效果、画像质量和匹配质量。

## 3. 候选人侧用户故事

### 3.1 上传简历

作为候选人，我希望上传已有简历，让系统自动读取我的教育、工作、项目和技能信息。

验收标准：

- 支持 PDF 和 Word 简历。
- 系统能提取原始文本。
- 系统能生成结构化简历数据。
- 用户可以看到解析结果。

### 3.2 校对简历解析结果

作为候选人，我希望检查并修改 AI 解析出的关键信息，避免错误信息影响后续画像。

验收标准：

- 用户可以查看基础信息、教育经历、工作经历、项目经历和技能标签。
- 用户可以修改明显错误或缺失字段。
- 修改后的结果作为后续访谈和画像的输入。

### 3.3 进行 AI 访谈

作为候选人，我希望 AI 根据我的简历继续追问，而不是问泛泛的问题。

验收标准：

- AI 问题必须引用简历中的具体经历或缺失信息。
- 至少支持 3 轮上下文相关追问。
- 系统能从回答中提取结构化事实。
- 用户可以跳过不想回答的问题。

### 3.4 查看人才画像

作为候选人，我希望看到系统对我的能力、优势、风险和职业方向的总结。

验收标准：

- 画像包含 8 个核心能力维度。
- 每个维度包含评分、解释、证据和置信度。
- 画像包含优势、风险、职业偏好和推荐岗位方向。
- 不确定结论必须标记为低置信度。

### 3.5 生成简历版本

作为候选人，我希望基于人才画像生成不同投递场景的简历。

验收标准：

- 至少支持 ATS 版和 HR 版。
- 简历内容必须来自候选人简历或访谈事实。
- 不能编造公司、学校、项目、数据和成果。
- 用户可以复制或导出生成结果。

## 4. HR 侧用户故事

### 4.1 输入岗位需求

作为 HR，我希望用自然语言描述岗位需求，而不是填写复杂表单。

验收标准：

- 支持一段自然语言岗位描述。
- 系统能拆解岗位名称、经验、技能、职责、软能力和偏好。
- 信息不足时，系统能标记缺失项。

### 4.2 查看候选人推荐

作为 HR，我希望看到按匹配度排序的候选人列表。

验收标准：

- 每个候选人包含总匹配分。
- 每个候选人包含经验、技能、画像、职业倾向分项得分。
- 每个推荐必须包含匹配理由。

### 4.3 查看风险点和面试问题

作为 HR，我希望知道候选人可能不匹配的地方，以及面试时应该追问什么。

验收标准：

- 每个候选人包含风险点。
- 每个风险点要说明来源。
- 系统生成 3-5 个建议面试问题。
- 面试问题应围绕不确定点或关键岗位要求。

### 4.4 导出到现有工作流

作为 HR，我希望把 AI 生成的候选人信息复制或导出到现有 ATS、Excel、邮件、飞书或企业微信中，而不是必须切换到一套新系统。

验收标准：

- 支持复制候选人一页摘要。
- 支持导出 Excel / CSV 候选人列表。
- 支持复制推荐理由、风险点和面试问题。
- 支持生成邮件或协作工具可转发摘要。
- 深度 API 集成不作为 MVP 必做项。

## 5. 功能范围

### 5.1 MVP 必做

候选人侧：

- 简历上传。
- 简历文本提取。
- Resume Agent 结构化解析。
- 简历解析结果展示。
- Interview Agent 多轮追问。
- 访谈事实抽取。
- Profile Agent 人才画像生成。
- Resume Builder Agent 生成 ATS 版和 HR 版简历。

HR 侧：

- 岗位需求输入。
- 岗位画像生成。
- Match Agent 候选人评分。
- 推荐结果展示。
- 候选人摘要复制。
- Excel / CSV 导出。
- 邮件或协作工具摘要生成。

内部调试：

- Agent 输入输出日志。
- Prompt 版本记录。
- 原始 JSON 查看。

### 5.2 MVP 不做

- 多企业账号体系。
- ATS 深度 API 集成。
- 自动投递。
- 自动联系候选人。
- 付费订阅。
- 背景调查。
- 大规模向量检索优化。
- 复杂工作流审批。

## 6. 核心数据对象

### 6.1 Structured Resume

包含：

- 基础信息。
- 教育经历。
- 工作经历。
- 项目经历。
- 技能标签。
- 证书和奖项。
- 原始文本引用。

### 6.2 Interview Facts

包含：

- 用户回答。
- 抽取出的事实。
- 事实对应的经历。
- 置信度。
- 是否可用于画像。

### 6.3 Talent Profile

包含：

- 8 个能力维度评分。
- 优势。
- 风险。
- 职业偏好。
- 推荐岗位方向。
- 证据链。
- 置信度。

### 6.4 Job Profile

包含：

- 岗位名称。
- 工作年限。
- 核心职责。
- 必备技能。
- 加分技能。
- 能力要求。
- 职业倾向要求。

### 6.5 Match Result

包含：

- 总分。
- 分项得分。
- 推荐理由。
- 风险点。
- 建议面试问题。

### 6.6 HR Export Package

包含：

- 候选人一页摘要。
- ATS 友好字段。
- Excel / CSV 行数据。
- 邮件正文。
- 协作工具转发摘要。
- 面试评价表字段。

## 7. 非功能要求

### 7.1 可解释

任何画像和匹配结论都必须能追溯到简历或访谈证据。

### 7.2 可修正

候选人可以修正简历解析错误，避免错误信息继续传递。

### 7.3 可审计

内部可以查看 Agent 输入、输出、Prompt 版本和中间 JSON。

### 7.4 不编造

系统不得编造候选人的经历、成绩、公司、学历、项目数据或证书。

### 7.5 兼容现有流程

HR 侧输出应优先支持复制、导出和转发，让结果可以进入 ATS、Excel、邮件和协作工具。MVP 阶段不要求第三方系统 API 集成。

## 8. MVP 验收标准

候选人侧：

- 能上传并解析一份 PDF 或 Word 简历。
- 能完成至少 3 轮上下文相关 AI 访谈。
- 能生成包含 8 个维度的人才画像。
- 人才画像每个结论都有证据或置信度标记。
- 能生成 ATS 版和 HR 版简历。

HR 侧：

- 能输入自然语言岗位需求。
- 能生成岗位画像。
- 能基于候选人画像生成推荐列表。
- 推荐结果包含分数、理由、风险点和面试问题。
- 能导出或复制候选人摘要、推荐理由和面试问题。
