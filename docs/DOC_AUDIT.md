# 文档审计：AI Talent Agent Agent Design V1.0

## 1. 原始文档摘要

原始文档 `AI_Talent_Agent_Agent_Design_V1.0.docx` 已经形成了项目的核心方向：

- 产品使命：让 AI 比 HR 更了解候选人。
- 产品愿景：构建全球最大的人才画像数据库。
- 核心流程：人才 -> AI 理解 -> 人才画像 -> 岗位匹配。
- Agent 架构：Resume Agent -> Interview Agent -> Profile Agent -> Talent Database -> Match Agent -> HR。
- 候选人侧流程：上传简历 -> 简历解析 -> AI 访谈 -> 人才画像 -> AI 简历生成。
- 企业侧流程：HR 需求 -> Match Agent -> 人才数据库 -> 候选人推荐。

## 2. 已经明确的内容

### 2.1 产品方向

项目不是单纯的简历优化工具，而是以人才画像为核心的 AI 招聘基础设施。

已明确的核心假设：

- 简历无法完整表达候选人的真实能力。
- AI 访谈可以补全简历缺失信息。
- 人才画像可以成为候选人和岗位之间的匹配中间层。
- HR 可以通过自然语言发布需求，由 AI 完成岗位拆解和候选人推荐。

### 2.2 Agent 分工

原始文档已经定义了 5 类核心 Agent：

- Resume Agent：解析简历，提取结构化信息。
- Interview Agent：通过多轮深度访谈理解候选人。
- Profile Agent：生成核心人才画像。
- Resume Builder Agent：基于人才画像生成多版本简历。
- Match Agent：拆解 HR 岗位需求并推荐候选人。

### 2.3 人才画像维度

原始文档已经列出 8 个核心画像维度：

- 学习能力。
- 逻辑能力。
- 沟通能力。
- 执行能力。
- 创新能力。
- 领导能力。
- 抗压能力。
- 职业稳定性。

### 2.4 匹配算法方向

原始文档已经给出初版权重：

- 经验匹配：30%。
- 技能匹配：30%。
- 画像匹配：25%。
- 职业倾向：15%。

## 3. 当前缺失内容

### 3.1 产品边界缺失

需要补齐：

- 第一版优先服务求职者还是 HR。
- 第一版的核心价值是人才画像、简历生成，还是岗位匹配。
- MVP 最小闭环到底是什么。
- 哪些功能明确不做。

如果不先收敛边界，项目容易同时变成简历工具、招聘平台、ATS、职业规划工具和人才库，导致开发范围失控。

### 3.2 用户场景缺失

需要补齐：

- 求职者为什么使用。
- HR 为什么使用。
- 不同用户的关键任务。
- 每个场景的输入、过程和输出。
- 用户如何判断结果有价值。

### 3.3 人才画像标准缺失

原始文档列出了画像维度，但还没有定义：

- 每个维度是什么意思。
- 从哪些证据判断。
- 如何评分。
- 信息不足时如何处理。
- 如何避免模型编造结论。
- 候选人视角和 HR 视角分别如何展示。

这是当前最需要优先完善的部分。

### 3.4 AI 访谈机制缺失

原始文档列出了访谈阶段，但还没有定义：

- 每个阶段的目标。
- 问题生成规则。
- 追问策略。
- 访谈轮数控制。
- 何时停止访谈。
- 如何把回答转成结构化事实。

Interview Agent 的质量会直接决定人才画像质量。

### 3.5 Agent 数据契约缺失

需要为每个 Agent 定义：

- 输入结构。
- 输出结构。
- 依赖数据。
- 失败场景。
- Prompt 约束。
- 是否允许不确定。
- 证据引用规则。

没有数据契约，后续研发很难稳定串联多个 Agent。

### 3.6 匹配解释机制缺失

匹配算法已有权重，但还缺少：

- 岗位画像结构。
- 分项评分规则。
- 推荐解释格式。
- 风险点生成规则。
- 面试问题生成规则。
- 匹配结果如何被 HR 使用。

## 4. 文档完善优先级

建议按以下顺序补齐文档：

1. 产品定义：先确定项目做什么、不做什么。
2. 人才画像：定义核心资产和评分标准。
3. AI 访谈：定义如何收集画像证据。
4. Agent 设计：定义 Agent 之间的数据契约。
5. 匹配设计：定义 HR 侧推荐如何解释。
6. MVP 路线：定义研发阶段和验收标准。

## 5. 当前阶段结论

AI Talent Agent 的核心不是“多 Agent”本身，而是“候选人理解系统”。Agent 架构只是实现方式，真正需要沉淀为资产的是：

- 画像维度。
- 访谈策略。
- 证据链。
- 匹配解释。
- 简历生成规则。

因此，下一阶段应以完善文档为主，暂缓进入具体代码开发。
