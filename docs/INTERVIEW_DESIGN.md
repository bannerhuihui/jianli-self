# Interview Agent Design

## 1. 设计目标

Interview Agent 的目标不是陪候选人聊天，而是围绕人才画像补全证据。

它要解决的问题：

- 简历中只有结果，没有过程。
- 简历中只有职责，没有个人贡献。
- 简历中缺少动机、偏好和复盘。
- 简历中难以判断软能力和潜力。

访谈结果必须能服务于：

- Profile Agent 生成人才画像。
- Resume Builder Agent 生成简历。
- Match Agent 判断岗位适配。

## 2. 访谈原则

### 2.1 基于简历上下文

问题必须引用候选人的具体经历或明显缺失信息。

不推荐：

> 请介绍一下你的优点。

推荐：

> 你在简历中提到参与了 XX 项目，其中你负责 YY 模块。这个模块当时最大的难点是什么？

### 2.2 一次只问一个重点

避免把多个问题塞进一句话，降低用户回答压力。

### 2.3 优先追问高价值经历

优先级：

1. 与目标岗位相关的经历。
2. 结果明确的项目。
3. 候选人承担关键角色的经历。
4. 简历中描述模糊但潜力较高的经历。

### 2.4 控制访谈长度

MVP 建议：

- 最少 3 轮。
- 推荐 5-8 轮。
- 最多 12 轮。

如果信息足够，应及时停止并生成画像。

## 3. 四阶段访谈

### 3.1 阶段一：经历探索

目标：

- 确认候选人简历中关键经历的真实性和完整性。
- 补全角色、背景、任务和结果。

适合问题：

- 你在这个项目中具体负责哪一部分？
- 这个项目的业务背景是什么？
- 最终结果如何衡量？
- 你个人贡献和团队贡献分别是什么？

产出：

- 经历事实。
- 项目背景。
- 个人职责。
- 初步成果。

### 3.2 阶段二：深度追问

目标：

- 挖掘候选人的思考过程、决策能力和解决问题方式。

适合问题：

- 这个项目中最难的问题是什么？
- 当时有哪些可选方案？
- 你为什么选择这个方案？
- 如果重新做一次，你会如何改进？

产出：

- 问题拆解能力证据。
- 决策逻辑证据。
- 复盘能力证据。

### 3.3 阶段三：能力验证

目标：

- 针对人才画像维度补齐证据。

适合问题：

- 最近一次快速学习新技能并用到项目中是什么？
- 有没有一次你推动别人配合完成目标的经历？
- 遇到沟通冲突时你怎么处理？
- 压力最大的一次交付是什么？

产出：

- 学习能力证据。
- 沟通能力证据。
- 执行能力证据。
- 抗压能力证据。

### 3.4 阶段四：职业倾向探索

目标：

- 了解候选人的职业目标、岗位偏好、行业偏好和稳定性。

适合问题：

- 你下一份工作最看重什么？
- 你希望继续深耕当前方向，还是尝试新方向？
- 哪类工作环境会让你发挥更好？
- 你不希望下一份工作出现什么情况？

产出：

- 职业偏好。
- 岗位方向。
- 稳定性信号。
- 匹配限制条件。

## 4. STAR 追问框架

Interview Agent 推荐使用 STAR 框架追问：

- Situation：当时背景是什么。
- Task：你要完成什么任务。
- Action：你具体做了什么。
- Result：结果是什么。

补充追问：

- Decision：你为什么这样做。
- Reflection：现在回看有什么反思。

示例：

```text
候选人：我负责了用户增长活动。

追问 1：这个增长活动当时的目标是什么？
追问 2：你具体负责哪一部分？
追问 3：你做过哪些方案选择，为什么？
追问 4：最后数据结果如何？
追问 5：如果重做一次，你会优化哪里？
```

## 5. 问题生成规则

Interview Agent 每次生成问题时，应考虑：

- 当前访谈阶段。
- 已有简历结构化信息。
- 已有访谈回答。
- 人才画像缺失证据。
- 用户回答质量。

问题优先级：

1. 补全画像高价值缺口。
2. 澄清简历模糊经历。
3. 验证关键能力。
4. 探索职业偏好。

禁止：

- 问与候选人经历完全无关的问题。
- 连续追问过于隐私的问题。
- 在没有证据时诱导候选人夸大经历。
- 使用审判式语气。

## 6. 事实抽取

每轮回答后，Interview Agent 需要抽取结构化事实。

结构示例：

```json
{
  "factId": "fact_001",
  "sourceTurnId": "turn_003",
  "content": "候选人在 XX 项目中负责用户分层策略设计",
  "relatedExperienceId": "project_001",
  "relatedCapabilities": ["logicAbility", "executionAbility"],
  "confidence": "medium",
  "usableForProfile": true
}
```

事实抽取规则：

- 只抽取候选人明确表达的信息。
- 不把推测写成事实。
- 对模糊回答标记低置信度。
- 事实必须关联到经历或画像维度。

## 7. 缺口识别

Interview Agent 应维护一个画像证据缺口列表。

示例：

```json
{
  "missingEvidence": [
    {
      "capability": "communicationAbility",
      "reason": "当前简历和访谈中缺少跨团队沟通案例",
      "priority": "high"
    }
  ]
}
```

下一轮问题应优先覆盖高优先级缺口。

## 8. 停止条件

满足以下任一条件时，可以停止访谈：

- 已完成最少 3 轮，且核心画像维度有足够证据。
- 已完成推荐 5-8 轮，剩余缺口不影响初版画像。
- 用户明确表示想结束。
- 用户连续多轮回答信息量不足。
- 已达到最大 12 轮。

停止时应输出：

- 已收集事实。
- 仍缺失的信息。
- 可生成画像的置信度。
- 建议后续面试验证的问题。

## 9. 用户体验设计

### 9.1 语气

应使用职业、友好、尊重的语气。

避免：

- 审问感。
- 否定感。
- 过度心理分析。

### 9.2 进度感

建议展示：

- 当前访谈阶段。
- 已完成轮数。
- 预计剩余问题数。

### 9.3 可跳过

用户应能跳过问题。

跳过后系统应：

- 记录该问题未回答。
- 将相关画像维度置信度降低。
- 必要时换一种方式追问。

## 10. 输出格式

Interview Agent 每轮输出建议包含：

```json
{
  "stage": "deep_dive",
  "question": "你在 XX 项目中遇到的最大难点是什么？",
  "questionReason": "需要补充逻辑能力和执行能力证据",
  "targetCapabilities": ["logicAbility", "executionAbility"],
  "extractedFacts": [],
  "missingEvidence": [],
  "shouldStop": false
}
```

## 11. 与其他 Agent 的关系

- Resume Agent 提供结构化简历。
- Interview Agent 基于结构化简历生成问题。
- Profile Agent 使用访谈事实生成人才画像。
- Resume Builder Agent 使用访谈事实补强简历表达。
- Match Agent 使用访谈事实解释匹配理由和风险。
